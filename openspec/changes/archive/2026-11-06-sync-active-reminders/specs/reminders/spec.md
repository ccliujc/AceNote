# Spec Delta

## MODIFIED Requirements

### Requirement: REM-05 Reminders use live in-app events

系统 SHALL 在有效提醒成功触发后，先登记到当前会话的统一活动集合，再向已订阅的窗口交付变化及到期提示。人物根据有效到期提示展示气泡，完整记录根据权威活动状态展示提醒中心；同一次触发只展示一条，多个提醒按计划时间及稳定标识排序。窗口尚未创建或单次事件交付失败不能删除已登记的活动提醒。

#### Scenario: 已打开的窗口收到提醒

- **WHEN** 人物与完整记录页面均已加载并订阅提醒，且一个计划成功触发
- **THEN** 人物显示对应标题，完整记录中的提醒中心显示同一提醒

#### Scenario: 不重复展示同一事件

- **WHEN** 完整记录页面再次收到同一次触发的提醒变化
- **THEN** 页面不为其额外增加一条相同提醒

#### Scenario: 触发时没有完整记录窗口

- **WHEN** 提醒成功触发，但用户尚未打开完整记录
- **THEN** 提醒保留在主进程的本会话活动集合中，不为展示它自动打开大窗口

#### Scenario: 单次窗口交付失败

- **WHEN** 提醒已经登记，某个窗口的事件交付失败
- **THEN** 其他提醒继续处理，已登记提醒仍可由后续活动查询取得，不因交付失败再次触发计划

### Requirement: REM-06 Received reminder cards can be dismissed locally

系统 SHALL 允许用户在完整记录中逐条关闭活动提醒，成功关闭时更新当前应用会话的统一状态，并让相关窗口移除同一次触发的展示。关闭仅影响活动提醒，不改变任务状态、截止字段或完成统计；关闭失败时保留仍有效的提醒及重试入口，不能仅在当前页面假装成功。

#### Scenario: 收起提醒卡片

- **WHEN** 用户成功关闭当前页面中的一条提醒
- **THEN** 该提醒退出本会话活动集合，相关窗口同步移除对应展示，关联事项的任务状态保持不变

#### Scenario: 关闭失败

- **WHEN** 关闭操作在主进程接受前失败，且提醒仍然有效
- **THEN** 提醒仍可查询、卡片保留并说明可以重试，不返回虚假的关闭成功

#### Scenario: 关闭后重建页面

- **WHEN** 某提醒已成功关闭，随后用户重新打开、重建或重新加载完整记录
- **THEN** 活动查询不再返回该次触发，页面不会从旧事件或历史记录恢复已关闭卡片

## ADDED Requirements

### Requirement: REM-08 Active reminders belong to the current app session

系统 SHALL 将活动提醒限定为本次应用会话内成功触发、尚未关闭、关联事项仍未完成且截止计划仍对应的提醒。活动集合独立于任务的记录日期和页面筛选；应用重启建立新的空活动集合，不从历史已触发记录恢复卡片或气泡，启动前到期的待触发计划继续按既有规则标记为错过。

#### Scenario: 重启不恢复旧活动提醒

- **WHEN** 上次会话存在已触发但未关闭的提醒，用户退出并重新启动
- **THEN** 新会话活动集合为空，不再次展示该提醒，原任务与触发记录仍保留

#### Scenario: 跨日期活动提醒

- **WHEN** 一条以前记录的未完成事项在本会话触发，用户正在查看其他记录日期
- **THEN** 有效活动提醒仍可查询，不因任务记录日期或页面状态筛选消失

#### Scenario: 未到期计划跨重启

- **WHEN** 应用重新启动时，一条未触发计划仍在未来
- **THEN** 该计划仍可在新会话实际到期后触发并进入活动集合，不提前成为活动提醒

### Requirement: REM-09 Active snapshots and updates form one consistent view

系统 SHALL 提供本会话活动提醒快照与变化订阅，使首次查询和后续变化能够形成一致视图；在查询期间触发或关闭的提醒不能遗漏、重复或被迟到的旧快照恢复。查询本身不触发提醒、不修改任务；查询失败必须与真实空集合区分，并允许重新获取状态。

#### Scenario: 首次查询期间到期

- **WHEN** 完整记录正在取得首次快照，同时新提醒触发
- **THEN** 查询与订阅收敛到包含该提醒的最新集合，同一次触发只显示一条

#### Scenario: 关闭后的旧查询晚到

- **WHEN** 已关闭提醒的最新状态已显示，关闭前发起的查询随后返回
- **THEN** 界面保留最新关闭状态，不重新显示旧卡片

#### Scenario: 活动查询失败

- **WHEN** 初次或刷新活动查询失败
- **THEN** 界面说明查询失败并提供重试，有已知状态时保留该状态，不把失败伪装成没有活动提醒

### Requirement: REM-10 Task changes invalidate obsolete active reminders

系统 SHALL 在任务成功完成、归档、移除或更改截止信息后清除不再有效的旧活动提醒，并同步相关窗口；任务恢复仅按原规则安排未来计划，不恢复旧活动展示。只修改标题等非截止字段时，仍有效的活动提醒保留并更新显示内容，不重新触发。失败的任务修改不能清除仍有效的提醒。

#### Scenario: 完成或归档已提醒任务

- **WHEN** 用户成功完成或归档一条正在活动提醒中的事项
- **THEN** 对应活动提醒及仍显示它的人物气泡退出，其他提醒保持，完成反馈仍可正常展示

#### Scenario: 改为新的未来截止时间

- **WHEN** 用户把已触发事项的截止信息改为未来时刻
- **THEN** 旧活动提醒退出，只建立新的待触发计划，新提醒在实际触发前不展示

#### Scenario: 移除截止信息或改为过去

- **WHEN** 用户移除事项截止信息或改为其他已过时刻
- **THEN** 旧活动提醒退出，不立即补发或生成替代活动卡片

#### Scenario: 仅编辑标题

- **WHEN** 用户修改活动提醒所属事项的标题，未改变状态或截止信息
- **THEN** 提醒继续活动并显示新标题，不重复触发，也不重新播放或延长已有气泡

#### Scenario: 任务修改未成功

- **WHEN** 完成、归档或截止修改因冲突或存储错误未提交
- **THEN** 系统不因该失败请求清除原有效活动提醒

#### Scenario: 计划同步异常不掩盖已提交状态

- **WHEN** 任务已成功提交完成或截止变化，但后续计划写入发生异常
- **THEN** 系统仍按已提交任务状态使旧活动展示失效，不撤销任务成功结果；后续可用查询继续核对有效状态

#### Scenario: 失效旧计划残留后到期

- **WHEN** 截止信息已成功改变，但旧待触发计划因同步失败仍然残留并到达原计划时刻
- **THEN** 系统核对当前任务及计划后不登记或展示该旧提醒，也不阻止其他有效计划正常处理

### Requirement: REM-11 Dismissal identifies the exact reminder activation

系统 SHALL 使用当前会话及本次实际触发的身份处理关闭请求，而不是仅按任务或可复用的计划标识关闭。相同触发的重复关闭应得到一致结果，已失效的旧引用不能影响新触发；上一会话或非法引用必须被安全处理，不修改其他提醒或任务。

#### Scenario: 旧关闭遇到新提醒

- **WHEN** 同一事项改期后再次触发新提醒，旧页面提交上一次触发的关闭引用
- **THEN** 系统不关闭新提醒，返回或要求刷新到当前权威状态

#### Scenario: 两处同时关闭同一提醒

- **WHEN** 两个请求同时关闭同一会话中的同一次触发
- **THEN** 活动状态至多发生一次有效移除，两者最终获得一致集合，不产生新的触发或任务变更

#### Scenario: 上一会话或非法关闭引用

- **WHEN** 请求携带上一会话的引用、非法标识或缺少必需身份字段
- **THEN** 系统拒绝该请求并给出可刷新或重试的反馈，不用任务标识或标题猜测要关闭的提醒
