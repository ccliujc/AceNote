- [x] 1.1 定义活动条目、带会话及 revision 的完整状态、严格关闭引用 schema，并为到期事件增加触发身份；通过 contracts 测试验证合法空态、稳定身份、非法 UUID、非法版本及缺失字段，确认既有持久化 Reminder / ReminderView 语义不变（V03、V08）。

## 2. 主进程会话活动状态

- [x] 2.1 实现主进程独占的活动服务、会话与触发身份；仅接受成功抢占的本次触发，支持稳定排序、登记前校验及关闭后重复登记去重；以固定时钟、注入标识和重复触发测试证明每次触发只形成一项，登记先于事件交付（V01、V03）。
- [x] 2.2 实现完整状态查询、版本递增与变化广播，批量核对失败不发布部分或虚假空状态；通过版本、重复无变化操作、读取失败和事件回调抛错测试，并在后端验收记录写明权威状态与交付失败边界（V02、V04）。
- [x] 2.3 实现会话及 activationId 精确关闭、重复关闭幂等、旧会话拒绝和返回当前状态；用两个客户端请求、关闭接受前失败、关闭后结果交付丢失及相同计划 ID 再触发的测试证明旧关闭不影响新提醒，也不修改任务（V03、V04）。
- [x] 2.4 实现按已提交任务和截止签名的活动核对、内容更新与失效移除；覆盖完成、归档、清空、未来及过去改期、时区变化、恢复、只改标题和失败任务写入；用服务测试证明只改名保留同一触发且不重新发 due（V05）。
- [x] 2.5 用已有版本 4 的临时文件库验证新会话不恢复历史 fired 或旧关闭状态，旧任务、计划和 F01 输入不被迁移或重写，未来计划仍能触发；记录无迁移、回退及本会话状态释放限制（V07）。

## 3. 调度、任务提交和退出接线

- [x] 3.1 在当前应用入口建立共享会话与活动服务，把成功 claim 接到活动登记后再广播，并在抢占前核对当前任务与计划时刻；保持错过扫描及 15 秒轮询，以调度及启动集成测试验证未开大窗口时登记、排序、抢占失败不登记、改期或清空后残留旧计划不触发，单条失效或交付失败不阻断后续有效提醒（V01、V04、V05、V07）。
- [x] 3.2 将编辑、圆圈及文字完成、候选确认、F01 恢复处理、归档和恢复等当前成功提交入口接入独立活动核对，修正编辑回调透传提交后提醒异常的路径；注入计划同步失败与任务写入失败，验证活动展示跟随已提交事实、任务成功不被冒充失败，并保留既有联动回归（V05、V09）。
- [x] 3.3 接入周期核对及单次退出清理，停止后禁止迟到回调再登记、广播或访问已关闭数据库；用定时器、已关闭连接和重复退出测试验证恢复及清理顺序，并更新后端验收记录（V04、V09）。
