## 3. 生命周期恢复与重复处理保护

- [x] 3.1 在单例服务增加按 intake ID 的活跃操作、状态与输入 revision 校验，先拒绝 busy、resolved 或过期请求再进入处理；用延迟 Promise 验证同一输入竞争只执行一次、不同输入仍可独立推进（V03）。
- [x] 3.2 将识别新增与明确转换统一为确定任务 ID 及结果关联，走原子提交，复用已知关联并保护已编辑内容；用重复转换、转换与重试竞争、已处理重试及晚到响应测试证明没有额外任务、覆盖或重复完成事件（V03、V04）。
- [x] 3.3 保存合法完成目标，增加恢复候选查询及旧目标缺失时的显式重新识别，确认时重查候选归属、任务状态和双 revision；通过多项变一项或零项、非候选 ID、过期任务、取消后继续及模型返回错误意图的测试（V05、V06）。
- [x] 3.4 接入窗口创建前的启动恢复，区分遗留 pending 与新活跃操作，不自动调用模型或重放完成；以文件数据库重开和固定跨天、跨时区请求验证原接收上下文保留，已有正确结果不重复处理（V01、V02）。
- [x] 3.5 在显式退出时使活跃令牌失效并禁止迟到写入，保留既有一次性清理顺序；以生命周期回归验证请求中退出不等待网络、不访问已关闭数据库，下次启动显示可恢复状态（V09）。
- [x] 3.6 为输入创建、开始处理、失败、待确认和处理成功发送输入变化通知，提交后才发送任务成功事件；用事件计数和广播失败注入测试验证终态不被广播异常改回失败，并更新后端验证记录（V03、V04）。
