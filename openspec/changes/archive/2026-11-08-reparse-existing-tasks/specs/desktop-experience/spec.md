# Spec Delta

## ADDED Requirements

### Requirement: DESK-16 Full records offer explicit task reparsing

系统 SHALL 在完整记录为三种状态的事项提供“重新识别”入口，展示原文、保留与覆盖的区别及可访问确认界面，默认选择保留。界面须表达处理中、成功、失败和冲突，阻止重复确认并提供适合错误的重试或刷新。交互保持浏览日期、筛选与无关草稿，不发完成动效，不改变人物及浮窗独立关闭规则。

#### Scenario: 打开或取消不发起识别

- **WHEN** 用户查看未完成、已完成或已归档事项，打开重新识别界面后取消
- **THEN** 界面展示该事项原文及两种模式说明，系统不调用模型、不改变任务，普通字段编辑仍可使用

#### Scenario: 键盘默认选择保留

- **WHEN** 用户用键盘打开重新识别确认界面
- **THEN** 初始焦点位于保留选择，Tab 焦点限制在对话框内；覆盖需用户明确选择，未开始识别时 Esc 可取消并恢复合理焦点

#### Scenario: 处理期间防止重复确认

- **WHEN** 用户已确认一种模式且请求仍在进行
- **THEN** 界面说明识别中，禁用两种确认及对话框取消操作，连续点击或按键不发起第二次请求；浮窗仍可独立使用

#### Scenario: 失败后明确重试

- **WHEN** 识别因网络、配置、非法结果或完成意图未提交
- **THEN** 对话框显示可理解的具体原因，保留原文及模式说明，允许用户明确再次选择或退出后手动编辑，不自动重试或伪造成功

#### Scenario: 冲突后刷新再确认

- **WHEN** 识别因事项已更新而发生版本冲突
- **THEN** 界面提示刷新记录；刷新只读取最新事项，不调用模型，取得最新版本后须由用户再次选择模式，不能把旧覆盖意图自动应用到新版本；刷新失败仍保留错误与重试入口

#### Scenario: 刷新成功不消费其他上下文

- **WHEN** 重新识别提交成功，列表、球场、浮窗和活动提醒收到变化，或用户在请求期间切换记录日期
- **THEN** 界面按当前浏览日期及筛选刷新，主窗口与浮窗草稿、F01 待处理输入及完成统计保持；非截止变化不重播人物提示

#### Scenario: 窗口收起与旧界面结果

- **WHEN** 用户在请求期间普通关闭完整记录，或 renderer 被重建，随后结果返回
- **THEN** 已接受的请求可在应用仍运行时按版本规则完成，人物与浮窗继续运行；重新打开后通过刷新展示结果，旧界面的迟到响应不能覆盖新界面或另一事项的反馈
