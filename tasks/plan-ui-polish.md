# 技术计划：AceNote ui-polish

状态：2026-10-29 用户以“继续”确认实施，执行进度见 `todo-ui-polish.md`。

依据：`../spec/SPEC-ui-polish.md`，2026-10-29。

## 1. 实施原则

- 沿用 React、TypeScript、原生 CSS、现有 contracts 和 IPC；本次不增加依赖。
- 仅修改渲染层和相应测试，不改数据库、解析/状态规则、提醒调度和原生窗口尺寸。
- 将布局优化和必要的交互修复分步实施；每步产出可运行、可截图的界面。
- 保留工作区现有未提交改动，实施前重新检查相关文件，按当前版本增量修改。
- 现有 `capture-page`、`task-list`、`reparse-dialog` 仍引用共享样式，调整时一并回归；不在本轮删除旧实现。

上述渲染组件已按职责实现，验证结果见 `verification-ui-polish.md`。本轮没有扩展为通用组件平台。

### 数据流

1. `LifecyclePage` 持有 `date`、`status`、`allTasks`、`summary`、草稿与交互状态。
2. 日期查询固定调用 `listTasks(date, 'all')` 和 `getDailySummary(date)`；现有状态筛选在前端派生，不改变顺序。
3. `visibleTasks` 同时传给球场和列表；筛选计数来自 `allTasks`；完成统计始终使用 `summary`。
4. 日期或数据事件触发刷新时使用递增请求序号或等价方式；只接纳当前请求，卸载后不更新状态。
5. 日期加载与同日期后台刷新分别处理：日期切换不把上个日期数据挂到新标题下；同日期刷新失败可保留已有数据并提示。
6. 创建、归档、恢复、编辑和完成结果仍由现有 API 决定；成功后刷新当前数据，失败保留草稿/弹窗/原状态。
7. 用提交锁同时约束按钮和快捷键；重试沿用既有 intake，所有异步入口都有明确错误处理。

- 确认 `SPEC-ui-polish.md` 的范围、紧凑布局、窄窗口球场折叠和“记录”按钮文案。
- 根据已确认规格生成 `todo-ui-polish.md`，任务保持小步、每项通常不超过约 5 个文件。
- 重新检查 Git 状态与相关源码，记录 1180×780 和 860×620 的原生窗口/内容区尺寸；使用隔离数据，不操作真实任务。
- 在临时演示或测试替身中覆盖 0/1/24/25 条任务、长文本与失败状态，不将模拟桥接写入生产代码。

交付：获确认的规格、任务清单、对照基线。规格和计划已获继续实施确认；历史基线保留，执行结果见任务清单和验证记录。

### 阶段 1：视觉变量与主窗口布局（P0）

- 新增系统字体与视觉变量，移除在线字体导入，补充全局 focus-visible。
- 移除大标题区和装饰侧栏，将品牌、日期和统计压缩到顶部。
- 提取紧凑输入组件；宽窗口输入/球场并排，窄或矮窗口球场默认折叠。
- 保留日期、筛选和任务顺序；先用当前数据接口验证首屏，再进入状态整理。

主要文件分两小步：

1. `tokens.css`、`styles.css`、`capture-composer.tsx`、`lifecycle-page.tsx`。
2. `court-view.tsx`、`date-navigator.tsx`、`styles.css` 和相关交互测试。

验收：A01–A04；有三条任务时，默认窗口看见三条、最小窗口看见至少一条。此时不宣称状态边界或原生桌宠已验收。

### 阶段 2：列表、筛选和异步反馈（P1）

- 改为按日获取全量记录，并派生状态计数、列表与球场；保留完成日期统计的独立口径。

- 历史日期提示新增去向；输入防重复和中文组合保护；重试、转换、归档、恢复失败有反馈。
- 精简任务行视觉层级，增加长标题换行、选中态和明确的忙碌操作。
- 编辑成功按当前日期刷新，避免筛选结果或统计停留在旧状态。

主要文件：`lifecycle-page.tsx`、`lifecycle-task-list.tsx`、`capture-composer.tsx`、`styles.css` 及相关测试；按数据流和呈现再拆小任务。

验收：A05–A08；以延迟响应、乱序响应和拒绝响应验证状态，不只检查新增的 className。

### 阶段 3：弹窗键盘与失败恢复（P1）

## 4. 验证计划

### 自动检查

实施后先运行每步关联测试，再统一运行：

```bash
npm run lint
npm run typecheck
npm test
npm run test:coverage --workspace @acenote/desktop
npm run build
```

现有覆盖率配置要求所覆盖关键模块的语句和分支均至少 80%；若当前基线不足，记录差额与归属，不能把未达到阈值写成通过。

重点新增行为：

- 快速切换日期的乱序返回、组件卸载和同日期刷新失败。
- 当天为空/筛选为空/查询失败三种分支；筛选计数与完成日期统计的区别。
- Cmd/Ctrl+Enter、中文输入组合、忙碌重复提交、失败保留草稿和沿用 intake 重试。
- 编辑/候选弹窗的初始焦点、Tab 循环、Esc、忙碌关闭保护和关闭后返回焦点。
- 提醒关闭拒绝后仍可操作；浮窗加载失败与重试。

### 人工/浏览器检查

| 场景                        | 检查内容                                                       |
| --------------------------- | -------------------------------------------------------------- |
| 1180×780、860×620、1440×900 | 首屏任务数、断点布局、无横向溢出、操作可达                     |
| 125% 缩放                   | 允许纵向滚动，按钮/长标题/日期控件不互相覆盖                   |
| 0/1/24/25 条任务            | 空状态、三态图案、稳定布局、24 球上限、剩余提示                |
| 长标题、2000 字原文、无日期 | 列表、弹窗、球场可访问名称、浮窗和桌宠气泡                     |
| 纯键盘                      | 输入、日期、筛选、任务编辑、候选、关闭与返回焦点               |
| 离线、减少动态效果          | 无在线字体/视觉请求，静态状态完整，非必要动画关闭              |
| 多条提醒同时出现            | 内部滚动、不遮挡弹窗、逐条关闭失败可恢复                       |
| macOS / Windows 原生        | 标题栏与内容尺寸、系统字体、日期控件、桌宠点击穿透、关闭即退出 |

## 5. 风险与处理

| 风险                                  | 处理                                                                              |
| ------------------------------------- | --------------------------------------------------------------------------------- |
| 当前有大量未提交更改                  | 每阶段先复读待改文件；不重置、不覆盖旧工作；改动逐步可审阅                        |
| 全局样式影响旧 capture 组件           | 视觉变量全局共享，组件布局选择器收窄；回归旧 capture/editor/reparse 测试          |
| 紧凑布局压缩球场                      | 窄/矮窗口默认折叠，展开仍保留24球与原布局，不改变状态图案                         |
| 统计被误写为“完成率”                  | 记录日计数和完成日统计分开命名，不用当前列表长度当完成统计分母                    |
| UI 刷新改动引入竞态                   | 请求序号、卸载清理、延迟 Promise 测试；不修改底层服务                             |
| 系统字体替换后行高变化                | 先统一字体，再测布局，最终在两平台检查中文长标题和日期控件                        |
| 桌宠气泡修复影响穿透                  | 保持窗口/IPC约定，原生检查关闭按钮、角色点击、拖动和透明区域                      |
| 原生 SQLite 的 Node/Electron ABI 不同 | 先记录环境；若遇 ABI 错误，按 README 恢复匹配运行时，再复测，不能当作 UI 测试通过 |
