# 技术计划：AceNote capture

依据：`spec/SPEC-capture.md`（已批准）

## 交付目标

从零搭建 Electron + React + TypeScript 桌面客户端与本地 NestJS 解析服务，交付本地单用户的文字提交、SQLite 原文保存、DeepSeek 字段解析、结果编辑、失败重试和重新解析保护。

同时建立 npm workspaces、依赖管理、环境变量模板、README、Git 忽略规则、构建与测试基线。本计划不实现账号、完整桌宠、每日状态、提醒或云端同步。

## 数据与接口设计

### SQLite

- 数据库文件放在 Electron `app.getPath('userData')` 下，测试使用独立内存数据库。
- `tasks` 保存规格规定的 UUID、原文、识别字段、记录时间、时区、解析状态、编辑时间和审计时间。
- `schema_migrations` 保存本地数据库版本；启动时按顺序执行迁移。
- 原文、初始状态与记录时间在同一事务写入；重试只按 UUID 更新，不重新插入。
- 更新解析结果时使用状态与本地修订条件，防止晚到响应覆盖较新的手动修改。
- 所有查询使用参数绑定；渲染进程不得直接获得数据库路径或 SQL 执行能力。

### 进程与网络边界

- 渲染进程通过受限 IPC 调用 `submitTask`、`listTasks`、`updateTask`、`retryParse` 和 `reparseTask`。
- Electron 启用上下文隔离、禁用渲染进程 Node 集成，仅暴露类型化 API。
- 主进程在本地保存成功后调用 `POST http://127.0.0.1:<port>/v1/parse`。
- 解析服务无状态，不写 SQLite；只转发必要文字和日期上下文，并返回校验后的字段。
- DeepSeek 密钥仅由服务端环境变量读取，错误日志不记录完整原文、认证头或上游响应正文。

## 实现顺序

1. **工程基线**：初始化工作区、应用骨架、依赖、脚本、说明文档和忽略规则，确认空应用与空服务可以启动。
2. **共享契约**：定义 Zod schema、请求响应类型、IPC 接口和稳定错误码。
3. **本地数据层**：实现 SQLite 初始化、迁移、事务保存、查询、编辑与幂等约束。
4. **解析链路**：实现 NestJS 代理和 DeepSeek 输出校验，再实现主进程队列、超时、失败与网络恢复重试。
5. **用户界面**：实现输入、待办列表、原文查看、字段编辑、状态反馈、重试与重新解析确认。
6. **集成验证**：串联提交、保存、解析、编辑、断网重试和应用重启，完成覆盖率与构建检查。

## 可并行与串行关系

- 工程基线必须先完成，避免各组件形成冲突配置。
- contracts 完成后，SQLite 数据层与 NestJS 解析服务可并行开发。
- React 界面可在 IPC 契约固定后与主进程队列并行开发，使用内存测试替身。
- 完整链路集成必须等待 SQLite、主进程队列、解析服务和界面均通过各自检查点。
- 不并行修改同一配置文件；依赖和根脚本统一在工程基线阶段确定。

## 风险与缓解

| 风险 | 缓解策略 |
|---|---|
| `better-sqlite3` 与 Electron ABI 不一致 | 固定 Electron 与依赖版本，配置原生模块重建，并在 macOS 启动检查中验证；Windows 构建单独验证 |
| DeepSeek 返回非 JSON 或字段不稳定 | 请求严格 JSON，使用 Zod 校验和字段白名单；非法结果进入可重试失败状态，不写入未校验字段 |
| 重试或双击产生重复待办 | 客户端预生成 UUID、数据库唯一约束和事务保证幂等 |
| 晚到响应覆盖手动修改 | 使用本地修订条件和 `editedAt`，重解析默认保留修改 |
| 相对日期受当前时间和时区影响 | 注入固定时钟与 IANA 时区，测试覆盖跨午夜和夏令时边界 |
| 密钥或原文进入日志与客户端包 | 环境变量校验、日志脱敏、主进程边界检查和构建产物检查 |
| 离线或本地服务未启动影响记录 | 原文保存与解析彻底解耦，界面保留可编辑原文并显示明确重试入口 |

## 验证检查点

### 检查点 1：工程可运行

- `npm ci`、`npm run typecheck`、`npm run lint` 和空测试集命令可执行。
- 桌面空窗口和本地服务可启动，服务仅监听 `127.0.0.1`。
- `.env`、数据库文件、密钥、构建产物和依赖目录均被 Git 忽略。

### 检查点 2：数据可靠

- SQLite 单元测试证明原文先保存、UUID 幂等、迁移可重复执行、重启后可查询。
- 模型返回的额外字段无法覆盖记录时间；用户编辑后的修订不会被旧结果覆盖。

### 检查点 3：解析可控

- 模拟 DeepSeek 的正常、超时、断网、非法 JSON 和缺字段响应全部通过接口测试。
- 未提及日期时返回 `null`；只有日期时不生成时间；模糊信息不被补全。
- 服务日志和错误响应不包含密钥、认证头或上游响应正文。

### 检查点 4：用户流程完整

- 界面测试覆盖提交、列表展示、编辑、失败提示、重试和重新解析确认。
- 端到端串联验证断网提交后重启仍可看到原文，恢复解析后没有重复记录。
- 界面不出现完整桌宠、状态、提醒或账号等未获批准范围外功能。

### 检查点 5：交付验证

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

- 所有命令通过，capture 语句与分支覆盖率不低于 80%，原文持久化和幂等分支全部覆盖。
- 在 macOS 完成实际桌面启动与核心流程检查；Windows 验证记录为发布前检查项，不伪造未执行结果。
- 对照 `spec/SPEC-capture.md` 的 10 条成功标准逐项记录验证结果。
