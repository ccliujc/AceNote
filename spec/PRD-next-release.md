## 1. 产品目标与用户场景

AceNote 继续以“桌面人物 + 日程浮窗”为日常入口，让用户快速记录事项、收到提醒并完成任务。下一阶段先解决记录和提醒的完整性，再让不具备开发环境的用户通过安装包试用，最后接入账号与云端能力。

本轮关注四个用户场景：

1. 断网、识别失败或应用意外退出后，用户能找回已经提交的原文并继续处理。
2. 用户主要使用人物和浮窗，在提醒触发之后才打开完整记录，仍能看到尚未关闭的活动提醒。
3. 识别结果不准确时，用户可以重新识别已有事项，并决定如何处理手动修改。
4. 朋友下载安装应用后，无需拉代码、安装 Node.js 或操作终端即可试用。

## 2. 已有能力与约束

以下能力作为后续需求的基础，继续保留：

- 原文先写入本地 SQLite，再请求自然语言识别；支持新增、文字完成、候选确认、手动完成、编辑、归档、恢复和每日完成统计。
- 启动只显示人物；单击、双击打开日程浮窗；完整记录按需打开，关闭大窗口不退出人物或浮窗；显式退出才结束应用。
- 澳网蓝主题、越前龙马三态透明 PNG、现有击球与庆祝动效、15 秒人物提示、紧凑日程列表。
- 单个明确时刻省略日期时默认提交当天；已过时刻不顺延明天；重试仍使用原输入的接收时间与时区。
- 提醒仅在应用运行时触发；只有日期时默认当地 09:00；退出或关机期间错过的提醒不补发。
- 人物提示的自动收起与任务是否完成相互独立。浮窗草稿目前只在本次应用会话中保留；未提交草稿的跨重启保存不列入本期。
- 每日列表仍按记录日期浏览；本期不改成按截止日期聚合的日历或“今日到期”视图。

本地原文持久化、组件单测通过和实际产品入口可用是三个不同的完成条件。历史清单中的勾选不替代本文件列出的实际路径验收。

## 4. 阶段 A：可靠性补齐

### F01：已提交输入的重启恢复与继续处理

**交付状态（2026-11-04）：** 已实现，见 [F01 验收记录](../tasks/verification-f01-input-recovery.md)。macOS 恢复与窗口交互通过隔离原生验收，Windows 未验证；OpenSpec 增量规格已同步，变更已归档至 [2026-11-04-recover-submitted-inputs](../openspec/changes/archive/2026-11-04-recover-submitted-inputs/proposal.md)。下列需求保留作为交付口径，不再代表待开发项。

**用户需求：** 已提交的文字即使识别失败或处理被中断，也能在下次启动后找到并继续处理。

**功能要求：**

1. 完整记录提供“待处理输入”入口，浮窗在存在待处理内容时提供数量与进入入口；不自动弹出大窗口。这里展示已提交的原文，不是尚未提交的草稿。
2. 列表包含处理中断、识别失败和待确认候选的输入，展示原文、接收日期、处理状态、可理解的失败原因和可执行操作；跨日期输入不能因默认查看今天而消失。
3. 启动后将上次被中断的请求呈现为可重试状态，不能永久显示为处理中。恢复网络后由用户发起重试，不静默执行可能改变任务状态的完成指令。
4. 支持重试识别、继续选择完成候选、明确选择“作为新待办”。重新计算候选时只使用当前未完成任务，并再次校验版本，不能沿用已经失效的候选直接完成。
5. 重试沿用原输入标识、接收时间、记录日期与时区；同一输入重试、重复转换或跨窗口操作，最多创建一个关联事项。已处理输入不可再次执行，晚到结果不能覆盖更新的手动修改。
6. 处理成功后从待处理列表移除，并刷新相关窗口；失败时保留原文与操作入口。关闭界面或取消候选选择只结束当前交互，不删除原文。

**验收案例：** 断网提交后退出并重启；在识别中退出并重启；有歧义候选时重启；跨天重试“12点吃饭”；两个窗口处理同一输入。以上场景均可找回原文，无重复事项、无错误完成、无记录日期漂移。

### F02：活动提醒查询与关闭状态同步

**用户需求：** 提醒已经触发时，即使完整记录窗口此前未打开，之后也能看到尚未处理的提醒。

**功能要求：**

1. 主进程统一管理活动提醒；完整记录首次打开、窗口重建或页面重新加载时，获取活动提醒快照并持续接收变化，两者衔接不能丢失事件或产生重复。
2. 本期活动提醒限定为：当前应用会话内已触发、尚未主动关闭、且关联任务仍为未完成状态（`open`）的提醒。多个提醒按计划时间排序，同一提醒只显示一条。
3. 完整记录中的“关闭提醒”更新统一状态并通知有关窗口；关闭失败时保留原提醒并允许重试，不能只在当前页面假装成功。
4. 人物气泡 15 秒自动收起或叉号收起仅影响气泡外观，活动提醒仍可在完整记录中查看；从提醒中心主动关闭后，正在显示同一提醒的人物气泡也应收起。
5. 完成、归档、移除截止时间或重新安排截止时间后，旧活动提醒退出展示；恢复任务只按现行规则建立未来提醒。旧提醒的关闭操作不能误关闭重新安排后的新提醒。
6. 应用重启不重新弹出上一会话的气泡或活动提醒；退出期间到期的计划继续标记为错过，不补发。本需求补齐本会话内的查询与同步，不新增提醒历史中心。

**验收案例：** 始终不打开大窗口直至提醒触发；气泡自动消失后首次打开大窗口；关闭后重建窗口；完成正在提醒的任务；关闭失败重试；退出后错过截止时间再启动。预期分别为活动提醒可查、关闭一致、无旧提醒残留且无重启补发。

### F03：已有事项重新识别

**用户需求：** 用户无需重复录入，就能重新识别已有事项，并保护自己的修改。

**功能要求：**

1. 当前完整记录中的事项提供“重新识别”入口，使用该事项的原始文字及原记录时间、时区；普通字段编辑继续可用。
2. 发起前展示“保留修改并识别”和“覆盖并重新识别”两种选择，默认保留修改；保留模式只补充空缺字段，覆盖模式以新识别字段替换旧识别字段。
3. 只更新标题、截止日期、具体时刻与对接人；不修改事项标识、原文、记录日期、完成或归档状态、完成时间和统计归属。
4. 模型返回完成意图时不得因此执行完成任务；提示本次无法作为已有事项的字段识别结果使用，保留原有数据。
5. 请求失败、密钥未配置或结果非法时保留原字段并说明原因；处理期间阻止重复请求。请求后若事项已被其他操作更新，应提示冲突，不静默覆盖。
6. 成功后刷新列表、球场及浮窗，并同步提醒；已完成或已归档事项不因重新识别而重建提醒。

**验收案例：** 手动改名后以两种模式重新识别；识别失败；识别中编辑事项；对已完成事项重新识别。默认保留有效修改，无重复事项、无状态误变及提醒误触发。

### F04：首次使用说明

**用户需求：** 使用者在首次发送识别请求前，能够了解原文保存、模型调用和提醒的基本规则。

**功能要求：**

1. 首次使用时在浮窗内或轻量引导中提供说明，不强制打开完整记录大窗口。
2. 清楚说明：原文先保存在本机；自然语言识别会把必要文字和日期、时区上下文发给 DeepSeek；识别需要联网及有效配置；提醒仅在应用运行时生效，退出期间错过的提醒不补发。
3. 首次识别请求前确保说明可见；用户暂不继续识别时，已提交原文仍保留，并可转为本地事项后手动编辑。后续实际采用托管解析时，应补充说明数据会经过运营方服务。
4. 记录本机已展示状态，普通重启不重复打断；设置中可再次查看。服务不可用或未配置密钥时仍能使用本地记录和已有任务的手动完成。

**验收案例：** 全新用户数据目录首次启动；未配置密钥；首次提交前查看说明；跳过识别后找回原文；重启不重复引导；从设置再次查看。

## 5. 阶段 B：可直接安装的本地试用版

### F05：应用内解析配置

**用户需求：** 试用者能够在应用里配置识别服务，无需查找和编辑环境变量文件。

**功能要求：**

1. 提供明确的设置入口，支持保存、更换和移除本人提供的 DeepSeek API Key；说明识别调用使用该密钥对应的账户额度。
2. 显示未配置、已配置、配置验证失败和本地服务不可用等状态；提供测试连接与重试操作。连接测试使用固定演示文字，不读取用户已有任务内容。
3. 已保存密钥仅显示掩码，应用重启后仍可使用；移除后停止后续模型请求，但本地原文、任务和手动完成继续可用。
4. 用户密钥使用操作系统安全凭据能力保存，通过受限的配置通道供本地解析服务使用；不写入任务数据库、浏览器持久缓存、日志或分发包，也不随应用预置开发者密钥。
5. 开发模式保留 `.env` 方式；若与应用内配置同时存在，必须在实施规格中明确优先级及界面当前生效来源，避免界面显示与实际调用不一致。

**边界说明：** 应用内录入使用者密钥是新增方案，会扩展现行 capture 规格中“仅从服务端环境变量读取”的约定。实施规格需同步明确录入、保存和读取的进程边界；本文件不将该方案描述为现有能力，也不沿用“用户输入的密钥从未经过设置界面”的错误表述。

**验收案例：** 首次保存、错误密钥验证、更换、移除、重启读取及安全存储不可用。失败有明确反馈，不能静默退回明文保存，分发包不含任何预置有效密钥。

### F06：安装包与解析服务自动管理

**用户需求：** 用户只需下载安装并打开应用，无需安装开发工具或维持终端运行。

**功能要求：**

1. 分别提供 macOS 和 Windows 的桌面分发产物；可分批交付，每次发布明确已支持的平台、处理器架构、系统版本和验证结果。
2. 安装包包含运行所需的桌面端、本地解析服务及原生模块，使用者无需安装 Node.js、npm、Python、C++ 工具或在本机编译 SQLite。
3. 应用启动自动启动并检查本地解析服务；显式退出时释放服务、窗口与调度器。关闭大窗口继续保留人物、浮窗和必要服务。
4. 启动中的服务、服务不可用与密钥未配置应有不同反馈；服务启动失败不能阻止原文保存或已有任务的本地操作，并提供重新尝试入口。
5. 本地服务仅对本机开放。多个应用实例或端口占用时不得误连到未知服务，不通过杀死其他程序解决冲突，用户能获得可理解的恢复提示。
6. 正常升级保留已有原文、任务、提醒配置和使用者密钥；迁移失败保护原数据并明确提示。安装说明应说明升级、卸载及用户数据保留规则。
7. 发布说明包含版本、下载入口、支持环境、已知限制、签名与安装提示的实际情况。自动更新不列入本期，先支持下载新版覆盖升级。

**验收案例：** 无开发环境的新机器安装并首次启动；配置后完成一次录入和手动完成；本地服务失败后恢复；关闭大窗口；显式退出；端口冲突；从旧版升级。全过程无需源码、终端或手工启动服务。

## 6. 阶段 C：账号与云端能力

### F07：账号、会话与云端数据归属

本模块保留 [SPEC-identity.md](SPEC-identity.md) 的“已批准但暂缓实施”状态。下列内容为后续需求，不作为本地试用版的前置条件。

**功能要求：**

1. 支持邮箱与密码注册、登录、当前设备退出、查看基本账号信息；凭据错误提示不区分账号不存在和密码错误。
2. 支持访问令牌、刷新令牌轮换、重启恢复会话；刷新凭据使用操作系统安全存储，退出后当前设备的刷新会话失效。
3. 云端数据具有明确账号归属；服务端验证所有读写权限，不能通过替换资源标识访问他人任务、状态、归档或提醒。
4. 登录、注册和刷新接口具备输入校验、必要限流与不含机密的审计记录。
5. 单独明确已有本地数据的账号绑定与迁移流程：展示待迁移范围并由用户选择导入；支持重复执行不重复导入、失败可恢复，并保留迁移前的数据保障措施。
6. 切换或退出账号时明确本地数据与账号缓存的访问边界，不自动把既有数据归给新账号，不让下一账号读取前一账号的数据。

**验收案例：** 注册、重复邮箱、错误登录、令牌过期与轮换、重启恢复、退出失效；两个账号交叉读写被拒绝；本地导入重试无重复；迁移失败可恢复；切换账号无数据串用。

**实施前须细化：** 本地模式与账号模式的入口、云端保存哪些实体、迁移和冲突策略、退出后的本地可见范围。云端长期保存与数据归属不等同于多设备实时同步，本期仍不承诺实时同步。

### F08：运营方托管的解析服务（可选）

**适用场景：** 希望试用者无需自行准备模型 API Key。该方案可独立于云端任务存储设计，是否采用由试用方式决定。

**功能要求：**

1. 模型密钥只保存在运营方服务，客户端通过受控接口请求解析；沿用原文先本地保存、严格结果校验、失败可重试和手动编辑保护。
2. 公共网络接口须具备身份验证或独立的受控试用凭证、额度与限流；账号模块未完成时，不能直接把当前无认证本地解析接口暴露到公网。
3. 明确试用者准入方式、调用额度、费用承担、服务可用性反馈及凭证撤销规则；不得通过分发运营方模型密钥实现免配置。
4. 更新首次使用说明，写清文本经过哪些服务以及是否保存；断网或服务不可用时仍保留本地记录和手动完成。
5. 托管解析不自动扩大为云端任务存储、跨设备同步或长期保存原文；若增加这些能力，分别纳入账号与数据规格。

**验收案例：** 授权用户调用成功；未授权、超额和已撤销凭证被拒绝；服务故障保留原文；客户端包不含运营方模型密钥；本地任务可在服务故障时继续查看和手动处理。
