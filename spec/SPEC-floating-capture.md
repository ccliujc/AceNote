# Spec：浮窗日程输入与网球人物桌宠

状态：2026-10-29 用户直接要求实施。本规格覆盖早期规格中的“浮窗只读”和“仅主窗口输入”约定，以及本次桌宠素材替换范围；其他任务、提醒和应用生命周期规则不变。

后续产品形态以 `SPEC-floating-first.md` 为准：大窗口按需打开，关闭独立，浮窗不再失焦自动收起。

2026-10-30 简洁浮窗视觉与 Enter 提交规则以 [SPEC-floating-minimal.md](SPEC-floating-minimal.md) 为准。

## 范围与交互

1. 单击桌宠打开约 360×560 的浮窗，自动聚焦输入；可直接输入“明天下午 3 点开会”等日程，也能输入完成指令。
2. 与主窗口共享 `LifecycleService`、原文先保存、2000 字上限、日期/时区解析、失败重试和多候选确认；不新增独立的数据存储或解析规则。
3. `QuickInputApi` 只新增提交、原 intake 重试、转换为新待办和候选选择接口，复用已有校验过的 IPC。
4. 提交期间防重复；失败保留草稿，解析失败明确说明原文已保存，并提供重试/作为新待办。
5. 多匹配在浮窗内选择，不强制打开主窗口；确认前不改变任务，失败保留候选。
6. 浮窗失焦保持显示，不因打开/关闭大窗口丢失上下文。关闭按钮/Esc 收起窗口，保留本次应用会话的草稿；有候选时 Esc 先取消候选选择；提交期间阻止关闭。应用退出不承诺保存未提交草稿。
7. 今天的记录、完成数、7 项上限和跨窗口刷新继续可用；浮窗重开时按桌宠位置重新定位，并限制在当前屏幕工作区。
8. 桌宠替换为原创卡通人物打网球形象：同一人物的持拍、击球、庆祝三张透明 PNG，保留拖动、打开浮窗、完成/提醒动效。

## 验收

- 浮窗可直接提交日程，成功清空草稿并同步每日记录；Cmd/Ctrl+Enter 和中文组合保护有效。
- 空输入、重复提交、API 拒绝、解析失败、无匹配及候选冲突都有正确反馈，不伪造成功。
- 输入/处理中失焦不销毁上下文，收起再打开仍是同一窗口；App 关闭后不残留浮窗。
- 浮窗内容在 360×560 下可滚动，输入和关闭入口可用；小屏幕定位不越界。
- 三张人物素材身份一致、透明、512×512、每张低于 500KB；资源在仓库内，离线可加载。
- 相关组件/IPC/窗口测试、lint、typecheck、全量测试和构建通过；原生行为与模拟/浏览器结果分别记录。

## 实施顺序

扩展最小浮窗桥接与窗口复用 → 增加输入、失败和候选 UI → 接入三态人物素材 → 测试和隔离预览 → 重启现有开发应用。

人物素材使用内置 imagegen；提示词和源文件路径在资源说明中记录。旧球形素材保留，应用改为引用新人物文件。
