# Spec：以日程浮窗为主的产品形态

状态：2026-10-29 用户直接要求实施。覆盖之前“启动显示主窗口”“双击打开主窗口”“关闭主窗口即退出”和“空浮窗失焦自动收起”的规则。

## 产品规则

| 入口或操作                                | 结果                                                     |
| ----------------------------------------- | -------------------------------------------------------- |
| 启动                                      | 显示桌宠，不创建或弹出大窗口                             |
| 单击桌宠                                  | 只打开/聚焦日程浮窗                                      |
| 双击桌宠                                  | 仍只打开浮窗，不打开大窗口                               |
| 系统激活（例如点击 Dock）                 | 打开/聚焦日程浮窗，不创建大窗口                          |
| 浮窗失焦                                  | 保持可见，继续显示输入与日程                             |
| 浮窗“打开完整记录”/桌宠右键“打开完整记录” | 按需创建或显示大窗口；浮窗继续运行和显示                 |
| 关闭大窗口                                | 收起大窗口，保留其会话状态；不退出应用，不关闭桌宠或浮窗 |
| 再次打开完整记录                          | 恢复同一大窗口和其中的界面状态                           |
| 浮窗收起按钮/Esc                          | 保持既有草稿/候选规则，只收起浮窗                        |
| 桌宠右键“退出 AceNote”或系统退出（Cmd+Q） | 退出整个应用，停止提醒调度器并关闭数据库与所有窗口       |

本次不增加托盘、开机启动或系统通知。日程保存、解析、候选确认、提醒及人物素材保持现有规则。

## 实现约定

- 窗口管理器启动仅创建桌宠；大窗口延迟到明确打开完整记录时创建。
- 大窗口的普通 `close` 事件拦截为 `hide`；真正退出前标记退出状态，允许所有窗口关闭，避免拦截 Cmd+Q。
- `closed` 只释放窗口引用，不承担退出整个应用的职责。
- 系统激活与桌宠点击均走浮窗路径；重复激活复用窗口，加载期间不提前显示空白窗口。
- 关闭大窗口和打开完整记录均不调用浮窗关闭接口；浮窗不因 `blur` 自动收起。
- 明确区分“收起窗口”与“退出应用”，同步更新界面提示和 README。

## 验收

1. 启动/激活/单击/双击的路径均不会创建或显示大窗口；浮窗可以正常输入日程。
2. 明确打开完整记录时才创建大窗口，加载完成后显示；重复打开复用同一窗口。
3. 大窗口关闭时拦截默认销毁并收起；桌宠和浮窗的引用、显示状态与草稿不受影响。
4. 真正退出会允许大窗口关闭，停止调度并关闭数据库，不被普通关闭拦截阻止。
5. 浮窗失焦及打开完整记录不再收起浮窗；手动收起与重开保留原有行为。
6. 窗口生命周期、点击和浮窗交互回归测试通过；lint、typecheck、全量测试与 build 通过。原生窗口行为单独记录，不以 mock 代替实际验收。
