## 1. 目标

保留深绿、奶油色、网球黄和网球场主题，把主窗口调整为适合每天使用的紧凑工作台。用户打开应用即可找到输入、日期、筛选和已有任务；状态、失败原因和后续操作清楚可见。

优化以现有 Electron + React + TypeScript 渲染层为主，复用现有 API 和任务语义，不增加组件库或远程视觉资源。

## 3. 范围与边界

### 包含

- 主窗口信息层级、首屏密度、日期/状态工具栏、输入区和列表排版。
- 球场与列表的布局关系、状态图例、选中反馈和窄窗口折叠展示。
- 统一颜色、字体、间距、圆角、按钮、反馈和键盘焦点。
- 输入、加载、空结果、失败、重试、候选选择、编辑的交互反馈。
- 提醒中心、今日待办浮窗的排版、长文案和错误处理。
- 保持现有桌宠资源与窗口尺寸，修复气泡在窗口内的裁切和关闭按钮可达性。
- 为新增或变化的行为补充有实际价值的测试，并执行尺寸、键盘、离线和弱动态检查。

### 不包含

- 数据库迁移、解析和完成匹配规则、提醒调度、API/IPC 契约改造。
- 一键完成、批量操作、拖拽排序、搜索、任务优先级、趋势图或新增页面。
- 账号、同步、深色模式、托盘、后台常驻、系统通知。
- 更换桌宠 PNG、生成插画、加载在线字体，或引入 UI/动画框架。
- 本次 ui-polish 原始范围不改变窗口安全边界；后续窗口入口及退出行为以 `SPEC-floating-first.md` 为准。

## 4. 设计方向与信息架构

### 4.1 视觉语言

沿用现有品牌，弱化大面积宣传文字和装饰侧栏，让任务内容成为主视觉。中文作为主要功能文案，英文仅保留在小量品牌装饰中。

建议视觉变量（具体色值在实现时按对比度检查微调）：

| 类别         | 约定                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| 背景与表面   | 奶油底 `#f4f1e8`；卡片 `#fbfaf5`                                                                        |
| 主文字与品牌 | 深绿 `#183a31` / `#173f35`                                                                              |
| 强调         | 网球黄 `#d7ef78`，用于深色按钮或选中态                                                                  |
| 次文字       | 以 `#5d6e63` 为起点，避免用低透明度表达必要信息                                                         |
| 状态         | 成功深绿；逾期/失败暖红褐；归档中性色，同时提供文字或图案                                               |
| 字体         | 系统字体：`-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', sans-serif` |
| 字号         | 主标题 24–28px；任务标题/输入 15–16px；操作/元信息 12–14px；纯装饰最低 11px                             |
| 间距与形状   | 4px 基准；常用 8/12/16/24；卡片圆角 10–12px；控件圆角 6–8px；轻边框、少量阴影                           |
| 控件         | 常规点击区至少 32×32px；主要提交按钮至少高 40px；提供 hover、focus-visible、busy、disabled              |

所有必要文本与背景的对比度目标至少 4.5:1；控件边界和焦点指示目标至少 3:1。颜色不能作为状态的唯一提示。

### 4.2 主窗口布局

宽窗口（内容宽度 ≥1040px）：

```text
┌───────────────────────────────────────────────────────────┐
│ AceNote                                本地优先           │
├───────────────────────────────────────────────────────────┤
│ 每日记录       [前一天] [日期] [后一天] [今天]   当日完成 N │
├──────────────────────────────────┬────────────────────────┤
│ 记下一件事，或告诉我哪一项已完成 │ 每日球场 · 状态图例    │
│ [紧凑的统一输入区域]             │ [最多 24 个任务球]     │
│ 字数 / 平台快捷键       [记录 →] │ [超出数量提示]         │
├──────────────────────────────────┴────────────────────────┤
│ 当日记录 N       [全部] [未完成] [已完成] [已归档]         │
│ 状态 · 任务标题                         编辑 / 归档或恢复 │
│         截止时间 · 对接人 · 必要的识别反馈                 │
│ ……                                                        │
└───────────────────────────────────────────────────────────┘
```

- 品牌栏约 48–56px；取消独立的两行大标题，口号缩为一行辅助文字。
- 输入和球场使用两列；球场列约 300–340px；输入保持主要操作权重，两者默认高约 180–210px。
- 日期在所有当日数据视图之前，清楚表达查询范围；状态筛选在列表入口，统一影响球场和列表。
- 不创建空导航项；装饰侧栏移除，品牌归入页头。
- 页面采用一个主滚动区，工具栏不依赖 hover 才能操作。

窄窗口（860–1039px）或内容高度不足 700px：

- 改为单列；优先保留品牌、日期、紧凑输入、状态筛选和任务。
- 球场默认收起为约 36–40px 的“球场概览 · N 项”按钮；展开查看原有球场，支持再次收起。
- 折叠仅改变展示，日期、筛选和任务数据不变；按钮提供 `aria-expanded`。跨断点回到默认布局，不做新的持久化设置。
- 工具栏可换行，任务操作可移动到行尾下一行，不能遮挡标题或产生横向滚动。
- 用户主动扩展输入、球场或阅读长内容后允许正常纵向滚动。

### 4.3 首屏目标

以下使用默认收起/未聚焦输入、无错误提示、100% 缩放、至少 3 条短标题演示任务测量：

- 1180×780 内容视口：完整显示输入、日期、状态筛选及至少 3 条任务。
- 860×620 内容视口：完整显示输入、日期、状态筛选及至少 1 条任务。
- 实际 Electron 默认 1180×780 和最小 860×620 外框分别复测；如系统标题栏压缩内容空间，继续使用紧凑布局达到相同的任务可见性目标。
- 1440×900 内容视口：主内容不无限拉宽，长行仍易阅读。

## 5. 组件与交互规格

### 5.1 统一输入

- 主按钮改为“记录”，输入说明明确“一句话新增，或描述已完成事项”；保留品牌口号作辅助。
- 保留 2000 字限制及 Cmd/Ctrl+Enter。界面按平台显示快捷键；中文输入法组合阶段不得触发快捷提交。
- 空白或正在提交时阻止按钮和快捷键重复提交；处理中仍可浏览记录。
- 发起提交后保留当前草稿；仅在成功新增、成功完成或明确转换为新待办后清空。失败或候选未决不丢草稿。
- 成功消息轻量展示；错误与重试入口就近展示，使用 `role="status"` / `role="alert"`。
- 浏览历史日期时标明“正在查看历史记录，新记录仍保存在今天”，不把所选日期传作记录时间。
- 不把“刷新列表”当作“重试识别”；重试复用原 intake ID，转换操作复用现有接口。

### 5.2 日期、筛选和统计

- 初始日期为设备今天；保留前一天、后一天、日期输入和今天入口。
- 默认仍为“全部”；四个筛选使用可访问的按钮组选中态，例如 `aria-pressed`。
- 一次查询获取所选日的全部记录；前端按原顺序派生状态筛选、球场和筛选计数，避免计数随当前筛选丢失。
- “当日记录”和各状态计数来自 `recordDate`；“当日完成”继续使用 `getDailySummary(date)` 的 `completionDate` 口径。两者不能计算成一个完成率。
- 日期切换启动明确的加载状态；过期请求不得覆盖当前日期。切换日期或筛选不清空输入草稿。
- 当天完全无记录、当前筛选无结果、查询失败、加载中分别展示不同信息；筛选无结果提供“查看全部”。
- 新增记录在当前历史日期不可见时，成功消息提供“回到今天”，不自动打断历史浏览。

### 5.3 任务列表与球场

- 列表首行突出标题和状态；次行展示截止信息、对接人等必要信息；完整原文与记录时间仍可从编辑查看。
- 长标题和原文不能顶出操作区；主列表允许换行，今日浮窗截断时提供可访问的完整名称。
- 编辑、归档和恢复始终可发现；请求中显示对应任务的忙碌状态，失败保留原状态并给出反馈。
- 本轮不增加“标记完成”按钮；完成继续使用现有文字输入和候选流程，避免增加服务接口。
- 保持空心/实心/斜线图案、确定性布局和 24 球上限，增加可见图例。球场采用与列表相同的筛选结果。
- 点击任务球继续打开对应编辑；列表内该任务同步显示选中样式，键盘也可通过编辑按钮进入同一流程。
- 超出数量提示根据布局指向“任务列表”，不硬编码“下方”，以适配并排布局。

### 5.4 编辑与候选弹窗

- 共用弹窗外观和焦点管理：打开时聚焦首个合适控件，Tab/Shift+Tab 保持在弹窗内；关闭后恢复到触发控件，触发控件消失时回到输入区。
- 空闲时 Esc、取消/关闭均可退出；请求中阻止重复提交和关闭，结束后恢复操作。
- 保留字段校验、revision 冲突提示、不可修改原文和记录时间的规则；冲突和保存失败不丢弃已填写字段。
- 候选选择失败时保留候选并提示，选择成功后才关闭；不自行完成或改写候选事项。
- 保存成功后刷新所选日期的数据和统计；焦点与提示不依赖弹窗销毁后的控件。

### 5.5 提醒、今日浮窗与桌宠气泡

- 提醒中心限制整体高度并允许内部滚动，长标题换行，不能覆盖弹窗主要操作；不新增提醒规则或提醒记录中心。
- 关闭提醒失败时保留提醒并给出可重试反馈；同一提醒继续按现有 ID 去重。
- 日程浮窗已扩展为约 360×560，支持自然语言输入及候选确认；保留 7 项列表上限、剩余数量和打开主窗口入口，收起/草稿行为以 `SPEC-floating-capture.md` 为准。
- 浮窗共享系统字体与状态色，必要文字至少 12px；查询失败提供错误和重试，不能显示成没有任务。
- 桌宠气泡及其关闭按钮完全位于 220×220 客户区内；长消息允许局部滚动或受控换行，关闭按钮保持可见。
- 原生实测气泡关闭点击不触发角色拖动/打开今日浮窗，透明区域仍可穿透；本次经用户要求更换为人物素材并扩大日程浮窗，详见 `SPEC-floating-capture.md`。
- 主窗口和浮窗补充弱动态样式；减少动态效果时关闭非必要缩放、位移和脉冲，任务状态仍可识别。
